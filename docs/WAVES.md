# 鸣潮可选整合

`qodex-v0.6.0` 使用 gsuid_core 与作者原版鸣潮插件。游戏功能公开默认关闭；只安装依赖不会替你开通自动签到或体力提醒。远程自助绑定是独立的显式选项。Windows/Codex/QQ 部署前提仍见[部署指南](DEPLOYMENT.md)。

## 安装与开关

先完成Qodex向导与本机DPAPI初始化，并安装 Python 3.11 x64，再在仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Install-Waves.ps1 -Python "C:\Python311\python.exe"
```

仅需要远程自助绑定时追加 `-RemoteLogin`。安装器使用官方/作者固定提交来源；源码、Python环境、资源和数据在本部署 `state/waves`，不复用其他部署目录。完成后重启Qodex加载安全密钥，再从控制台启用；来源、精确版本与 GPL 范围见[第三方说明](../THIRD_PARTY_NOTICES.md)。

控制台“鸣潮”区分别保存全局与当前会话游戏开关。全局默认 `enabled:false`；当前会话 `null` 继承。全局关闭优先于会话开启。两分区共用会话选择；切换页保留草稿，仍需在对应区域保存。

开启游戏工具在下个空闲点/新线程生效。新 Codex 上下文载入最近100条有效本地消息和当轮检索记忆；全部本地历史、长期记忆及旧绑定仍保留供回退，旧原生隐藏压缩状态不声称完整复制。未启用会话保留其原绑定。

## 使用与支持范围

启用并放行的会话可发 `ww帮助`。明确 `ww` 指令独占游戏处理，不再触发另一份聊天回答；普通自然语言由当前聊天模型从实际目录调用游戏工具并使用原版结果。模型不能改用别人凭据、跨会话发送目标或任意本机文件。参数与当前能力以原版帮助和控制台实际目录为准。

| 分类 | 例子 | 边界 |
| --- | --- | --- |
| 公开只读 | 帮助、攻略/图鉴、日历、公告、角色持有率、深塔/冥海/矩阵出场率 | 不需自己的游戏账号；可能因上游缺数据或服务失败返回安全提示。返回提示不算取得有效数据。 |
| 需绑定本人账号 | 角色面板、声骸综合评分、伤害/优化、练度、便笺、探索、本人战绩、抽卡记录 | 需本人国服数据；尚不能以未绑定夹具证明所有真实账号分支正确。 |
| 需额外授权 | 声骸截图 OCR/评分、跨群排行榜上传 | 依赖 ScoreEcho 的 xwtoken 或相应上游上传授权；缺失时明确标示待授权，不用 GPT 近似分数代替原算法，不静默换服务。 |
| 修改操作 | 绑定、签到、解绑、自动签到/体力订阅 | 登录核对摘要后由同 QQ 确认绑定；本人直接明确 ww 指令授权该操作，模型/自然语言修改须同 QQ 确认。模型不得代发确认。 |
| 未开放/不可用 | 任意账号导入/删除、任意自定义卡片写入、管理/凭据导出、公告自动订阅 | 未经安全边界开放的原版 handler 不等于发布版可用；邮件与其他游戏自动任务不提供。 |

## 自助绑定与本人确认

1. 在放行会话发送 `ww登录`；群内在原群 @申请人提供三分钟有效的临时链接。不要转发链接。
2. 在网页自行输入手机号/验证码并完成官方验证，不在群聊、Codex 或日志提交凭据。
3. SMS 验证后核对返回的昵称/UID 账号概要，再由同一 QQ 发送提示中的 `ww确认 ...` 提交绑定。验证码成功不会自动绑定；他人、引用和转发中的确认不能授权。

票据三分钟有效，过期重新请求。三分钟仅约束新确认输入；按时接受的任务等待实际完成，不在期限到达时强制失败。仅取得绑定交互的用户不会因此获得普通 GPT 私聊或其他修改权限。

### 一次绑定，多群使用

同一 QQ 在同一机器人成功登录并确认绑定一次后，可在该机器人已加入且允许鸣潮的其他群直接使用本人的绑定账号，无需逐群重复登录。绑定确认须在原申请会话由同一 QQ 完成；后续在其他允许群查询本人数据不需要重新走绑定确认。

每次使用仍检查目标群白名单、鸣潮全局/会话开关与暂停状态。每个 QQ 只使用自己的绑定，不能借用他人账号；该绑定不转移给不同 QQ 或另一个独立机器人。凭据过期、撤销或解绑后可能需要重新登录。跨群复用本人绑定不合并聊天历史/记忆，也不跨会话复制自动签到或体力提醒订阅。

暂停或撤销会话访问权限后，控制台仍可纯停用已有自动任务订阅；此入口不允许开通或借停用修改有效订阅。JSON不包含订阅，恢复不会开通订阅。备份文件恢复后会协调鸣潮策略与本部署所属服务；若响应 `policySynced:false` 并附 `policyError`，表示文件已恢复、服务同步仍不完整，需按提示检查状态。

本人直接发送 `ww签到`、`ww解绑`、`ww开启自动签到`、`ww开启体力提醒` 或相应关闭指令，明确指令本身授权该具体操作，无需第二条确认。模型通过工具或自然语言发起的签到、解绑、订阅修改必须先展示具体操作，再由同一 QQ 显式确认；他人发言、引用或转发不算本人授权。自动签到/体力提醒默认关闭；体力默认阈值180，可指定120–240，如 `ww开启体力提醒 200`。控制台可停用订阅，开通须本人操作。群提醒 @本人。暂停、关闭游戏或撤销白名单后停止相关处理，恢复不补发积压通知。

## 作者服务授权与真实结果

控制台“鸣潮 → 作者服务授权 · 全局”分别保存排行使用的 `WavesToken` 与 ScoreEcho 使用的 `xwtoken`，可独立设置或明确选择共用。密码框留空保留已有值，保存后清空输入；后台刷新保留未提交草稿。数据由当前 Windows 用户 DPAPI 加密，不写普通配置、历史、日志或 JSON 备份。两服务即使共用值也分别记录权限和验证状态。

| 状态 | 含义 |
| --- | --- |
| 未配置 | 没有保存对应服务授权。 |
| 已配置，待实际请求验证 | 已安全保存，尚未得到该服务有效业务响应。 |
| 授权已验证 | 实际业务请求返回有效成功结果。 |
| 授权失败 | 实际服务拒绝授权，如 401/403。 |
| 服务故障 | 网络、响应或图片处理失败，不等同于授权无效。 |

作者授权用于排行/评分，不替代玩家登录，也不是额外模型 API key。完整登录必须取得账号登录票据、本人国服角色与 B-AT 数据票据后才能进入待确认绑定；缺失不报告成功。已有本人绑定缺 B-AT 时，只在需要本人数据的查询前按当前绑定/凭据版本补齐；公开攻略等查询不触发玩家登录。角色列表使用本人的授权，不能借用其他账号。

排行沿用实际原版查询触发，不扫描补传历史。评分只接受当前或合法引用的截图及本人 QQ/UID/会话任务，沿用原版压缩（实际上传每张不超过 1 MiB）；必须取得真实可读结果图才算成功。上游拒绝、无图片或处理失败不能保留先前绿色状态。取消、暂停、撤权或授权更新后，旧请求/迟到结果不得写入新状态或发出，不自动重试。

用户已反馈鸣潮可用；这是用户反馈，不能替代本候选对每个官方账号/服务分支的验证。历史 142 项离线隔离测试也不能当成当前候选或真实 SMS、排行、评分全部通过。实际结果与未验项以[验证记录](VALIDATION.md)为准。

## 远程登录与运维边界

`config.waves.remoteLoginEnabled` 默认 `false`，与游戏开关分离。启用后 Quick Tunnel 仅公开受票据保护的绑定页面；控制台、OneBot、游戏 RPC 和早柚管理路径保持本机。域名变化使旧票据失效。

[Cloudflare 官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)将 Quick Tunnel 定位为测试/开发用途：无可用性保证、域名每次变化，最多200个同时在途请求且不支持 SSE。国内及 QQ 内可达性需本人验证，不能将临时链接视为稳定生产域名。

使用现有 Windows 启动面板管理本部署进程；状态/验证应分别看 QQ、Codex、游戏服务和远程登录。默认端口为 RPC8788、登录8789、隧道指标8790，须与其他服务端口区分。游戏凭据由当前 Windows 用户 DPAPI 加密；不要上传 `state/waves` 或真实配置。JSON 备份仅含非敏感游戏开关，不含游戏账户、凭据、票据、订阅或游戏图片。
