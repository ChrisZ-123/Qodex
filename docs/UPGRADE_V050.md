# v0.5.0 升级与完整回退

适用于公开 `qodex-v0.4.0`（基线 `09e7f3e`）升级至 v0.5.0。先保存工作并停止本部署，勿更新正在处理的任务。更旧版本先按[v0.4指南](UPGRADE_V040.md)处理独立 Codex 登录与旧数据。

## 升级前完整备份

用旧配置执行 `Control.ps1 -Action Stop`，确认本部署进程已结束，然后完整复制旧部署到独立备份目录。应包含旧源码及锁文件、`config.json`、整个 `state/`、角色、自定义资源，以及配置指向的任何外部记忆目录。备份需包含独立 `state/codex-home`、`state/generated-images`、DPAPI文件、会话映射与完整历史；这些是私人数据，不提交 Git 或公开分享。

DPAPI状态需同一 Windows 用户环境读取；复制到别的 Windows 用户不保证能解密，跨用户迁移应分别重新官方登录/本人绑定，不能改用明文规避。

控制台 JSON 仍是 `qq-codex-backup` **version:1**，兼容 v0.4.0。新增非敏感语音开关、可选转写历史元数据及游戏开关。旧备份缺少语音字段时全局关闭、会话继承；缺少waves章节时保留当前游戏设置，首次安装仍默认关闭。它不含音频、游戏账号/凭据、登录票据、自动任务订阅、图片本体、Codex登录/绑定或隧道远程启用项，不能替代完整目录备份。恢复不会重新发送历史或开启自动任务。

恢复文件后会按当前恢复设置协调鸣潮策略与本部署所属服务。响应 `policySynced:false` 和 `policyError` 表示文件已恢复但运行同步不完整；按控制台提示检查服务状态，不能据此宣称恢复后的模块已就绪。订阅不在JSON中，不会因恢复而开通。

## 更新与首次启动

1. 核对工作区改动并更新到发布标签 `qodex-v0.5.0`，运行 `npm ci`；不要用强制重置覆盖自己的修改或状态。
2. 原 Windows 启动入口和 `state/codex-home` 独立 ChatGPT 登录继续使用。先确认普通聊天、记忆、表情和图片状态正常。语音保持关闭，只有接受实验性限制时再启用。
3. 鸣潮是可选模块。需要时安装 Python3.11 x64，执行 `Install-Waves.ps1 -Python "C:\Python311\python.exe"`；只有明确需要远程绑定才追加 `-RemoteLogin`。运行状态放入本部署 `state/waves`，不复制本机生产部署的环境或账号库。
4. 检查 `config.waves` 端口与现有服务无冲突，再在控制台显式开启游戏全局/会话开关。远程绑定单独控制，自动签到/体力提醒仍默认关闭且需本人开通确认。
5. 执行 `Control.ps1 -Action Start`、`Status`、`Verify`，核对各模块状态及控制台保存；真实 QQ/SMS/签到验证只在本人明确选择的范围操作。

启用游戏工具时，在下个空闲点/新线程创建带工具的 Codex 上下文，载入最近100条有效消息及检索记忆。全部本地历史、长期记忆和旧 Codex 绑定保留供回退；旧原生隐藏压缩状态不声称完整复制。未启用会话保持原绑定。两分区共用会话选择且保留草稿，草稿须保存才能生效。

## 回退

先停止 v0.5.0 并另行保留其完整数据，再恢复升级前**配套的 v0.4.0 源码、依赖锁文件、配置和旧数据快照**，使用同一 Windows 用户运行 `npm ci`、启动和验证。不要只切换源码后让 v0.4.0 直接读取已被 v0.5.0 写过的新格式状态。旧模型绑定从旧快照恢复；保留的新版本数据可供之后人工迁移，但不会自动合并或重发消息。

若只关闭游戏，可保存全局关闭并确认服务状态；这与整套版本回退不同。删除游戏环境、账户或备份不属于默认回退步骤。
