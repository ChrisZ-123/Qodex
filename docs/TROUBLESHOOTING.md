# 故障排查

先从仓库根目录查看状态；若未运行，执行 `Control.ps1 -Action Start` 后再做连接验证。随后查看 `state/bridge.log`、启动失败时的 `logs/windows-supervisor.log` 与控制台的会话历史。分享日志或截图前删掉账号、群号、聊天原文、令牌和本机路径。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Control.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Control.ps1 -Action Verify
```

| 现象 | 检查与处理 |
| --- | --- |
| `Setup.ps1` 提示找不到 Node 或版本不足 | Windows 安装脚本要求 Node.js 24 或更新。安装后重新打开 PowerShell，再运行 `node --version` 与 `npm ci`。 |
| 找不到 Codex 或选中了 `codex.cmd` | 安装官方 Codex 桌面版或 CLI，在安装向导中给出原生 `codex.exe` 完整路径。仅有 npm 的 `.cmd` 包装器不能满足此部署流程。 |
| Codex 账号或模型不可用 | 停止本部署，运行 `scripts/windows/Login-Codex.ps1` 完成 Qodex 独立目录的官方 ChatGPT 登录，再运行 `Setup.ps1` 检查模型。桌面端已登录不代表本部署已登录；API key 鉴权不支持，也不会自动换模型。 |
| `thread already has an active writer` 或旧会话不能恢复 | 确认正在使用本部署 `state/codex-home`；升级用户按[v0.4 升级指南](UPGRADE_V040.md)完成独立登录，并在**停止本部署**后选择迁移机器人映射的旧原生会话。不要删除锁文件或复制登录凭据。迁移失败会保留原映射与源文件。 |
| 桥接启动了但 QQ 没有会话 | 确认 SnowLuma 已登录 QQ、启用 OneBot WebSocket 服务端、URL 与令牌一致；确认目标群/私聊在白名单，黑名单没有覆盖。白名单为空时默认不放行。 |
| 会话里有消息，却没有 QQ 回复 | 看控制台是否暂停、模型是否选择不接话、是否有“模型请求失败”或“QQ 发送失败”事件。模型会根据群聊上下文保持安静，不能以无回复单独判断为故障。暂停期间的消息不会在恢复后自动补交。 |
| HTTP 426、发送表情或同步收藏失败 | `snowluma.httpUrl` 应指向 OneBot **HTTP API**，不是 WebSocket 的 3001 端口；检查 SnowLuma 的 HTTP 服务、access token 和本机回环地址。 |
| 图片未被自动收藏 | 仅允许群中由 OneBot 明确标记为表情的图片会进入自动收藏；普通图片和私聊图片不会。达到 100 张时暂停新增。可在控制台检查表情设置并手动同步 QQ 收藏。 |
| 生图未触发或引用改图失败 | 检查本会话实际 `imageMode`；公开默认仅处理明确的生图/改图请求。引用图只允许来自当前会话且能读取的消息；失败时重新发送原图。查看运行记录中的排队、生成、取消与发送阶段，不会自动重试。 |
| 备份恢复后图片显示不可用 | JSON 只含生成图片元数据，不含 `state/generated-images` 文件；从完整目录备份恢复对应文件，保持会话路径和文件名。不要从其他群借用图片。 |
| 合并转发只有部分内容 | 控制台历史会标出读取失败或截断；当前上限为三层、八份、一百节点、两万字符、五张图片和十五秒。OneBot 可能已展平内层记录，无法据此判断真实递归是否发生。 |
| 控制台打不开或提示未授权 | 用 `Control.ps1 -Action OpenConsole` 打开页面，将本机弹窗中的令牌复制到浏览器登录表单；检查控制台端口、进程状态及是否在正确的 Windows 用户下运行。不要把令牌或带令牌的访问链接分享出去。 |
| `state/secrets.dpapi` 无法解密 | 该文件受创建它的 Windows 用户环境保护。回到原用户运行；迁移机器时备份聊天数据后，安全重新初始化并输入 OneBot 令牌。不要把它改成明文 JSON。 |
| 端口占用 | `Setup.ps1` 会检查 WebUI、OneBot、控制台与控制服务端口是否不同。确认占用程序并在配置中选另一可用端口，重启后验证。 |
| 向导拒绝 `localhost`、IPv6 或无端口地址 | 当前 Windows 向导要求 OneBot HTTP、WebSocket 与 WebUI URL 使用字面量 `127.0.0.1`、显式端口；五个服务端口必须不同，范围为 1024–65535。 |
| `git pull --ff-only` 失败 | 查看仓库是否有本地改动或分叉；保留并审阅差异，不要用强制重置覆盖 `config.json` 或 `state/`。 |
| 升级后旧版记忆文件变成条目 | v0.3.0 首次读取旧记忆时保留 `memory.json.legacy-v1.json`，再写 schema 2；分会话逐次发生。旧版程序不能直接读取新版文件。回退须恢复升级前**完整旧版源码及数据**，包括外部记忆目录，见[升级指南](UPGRADE_V030.md)。 |
| 保存设置、记忆或图库时出现 409 | 资料已在打开页面后被其他操作更新。重新加载对应面板，检查新值后再保存；记忆还会核对条目版本，表情备注核对原备注与来源。备份预览过期或资料变化时须重新预览，不应反复提交旧请求。 |
| 取消回复显示“取消未确认” | Codex 中断请求未得到确认，运行记录会保留该状态。等待任务结束，或重置该会话上下文以隔离旧回复。取消只影响当前轮，后来排队的新消息不随之删除；重置会清除当前及排队回复。 |
| 某个会话没用刚选的全局模型/人格 | 查看“当前会话独立设置”是否覆盖了全局选择。保存只从下一轮生效，已开始的回复仍用它启动时的设置。全局速度与压缩阈值仍作用于所有会话。 |
| 记忆内容似乎没有被模型使用 | 检查会话记忆是否关闭、条目是否停用、相关内容是否命中本轮检索；运行记录可查看实际提供的条目。置顶条目会优先提供。模型不保证每轮都写记忆，本地检索和反馈不会训练模型。 |
| 备份 JSON 无法恢复 | 先看预览中的格式、章节、角色引用与账户可用模型检查；预览 ID 10 分钟后失效，当前数据改变也需重做预览。JSON 不含 DPAPI、Codex 登录态、图片本体和全部状态；升级回退请使用完整目录副本。 |
| 关闭控制台后仍在回复 | 控制台只是网页。运行 `Control.ps1 -Action Stop` 停止桥接及由 Qodex 自动启动的 SnowLuma；若 SnowLuma 是手动启动的，需另行关闭。 |
| 电脑睡眠后不回复 | 睡眠、关机和断网期间本机进程无法实时接收并回复。唤醒后检查 SnowLuma、Codex 登录、`Status` 与日志。失败的模型批次不会静默自动重试。 |

模型搜索网页属于 Codex 的原生能力，只在模型认为需要时发生。没有联网搜索记录并不自动说明配置失败。控制台可直接选择模型和推理强度；列表为空或刷新失败时检查 Codex 登录和连接。加速档位不是固定提速承诺。重置会话保留长期记忆，因此模型仍可能知道记忆中的约定；需要修改这些内容时使用记忆编辑入口。手工修改配置或本机端口前，先用旧配置执行 `Stop`，再编辑配置、`Start`、`Verify`。若问题可稳定复现，请用[问题模板](../.github/ISSUE_TEMPLATE/)提交脱敏的步骤、预期/实际行为、版本与日志片段。
## 语音与鸣潮补充

语音默认关闭且实验性。先核对全局/会话 `voiceEnabled` 和暂停状态，再查看历史中的转写错误及运行耗时。“收到语音”不等于取得文字。已有本机QQ手动转写和SnowLuma转写均失败的证据，但原因未确定；不要将失败猜成语音内容，也不要把机器人静默当作成功。见[语音限制](VOICE.md)。

鸣潮默认关闭，安装与启用分开。核对Python3.11 x64、`state/waves`安装状态、全局/会话开关、白名单/暂停和8788/8789/8790端口冲突。远程自助绑定默认关闭，安装时需显式 `-RemoteLogin`；Quick Tunnel临时域名变化使旧票据失效，重新请求本人登录即可。手机/QQ可达性及真实SMS由本人验证，不因控制台显示就绪宣称成功绑定。

“未绑定”“上游无数据”“待授权”是可解释状态，不是完整账号功能成功。声骸截图评分/排行上传需对应上游授权。自动签到、体力提醒均默认关闭，JSON恢复不重新开通；本人直接明确ww指令授权具体操作，模型发起修改须同QQ确认。三分钟限制新确认输入，不限制已接受任务完成。请按[鸣潮支持矩阵](WAVES.md)判断实际可用范围。

## v0.6.0 恢复与状态判断

- 模型列表为空：全局设置中查看加载/失败原因并点刷新；请求会合并且保留已成功列表，全局与会话目录分别维护。当前模型不在可用列表或强度无效时须自己选择，不会静默换模型。人格通过全局入口编辑；当前会话可恢复继承，已有明确覆盖仍保留。
- 模型持续未就绪：监督服务已启动时使用启动页“修复 Codex 连接”或 `Control.ps1 -Action RepairCodex`，再检查状态。它中止当前回复，只重启所属桥接/Codex，不重启 QQ、鸣潮或隧道，不重发旧消息。端口归属或代理格式错误会拒绝；只接受启用的本机127.0.0.1 HTTP代理，不改变系统代理。账号过期、网络或模型不可用仍需各自处理。
- 路由初始化失败/超时：精确的 workspace routing discovery failed/timed out 由现有健康检查恢复。登录错误、普通超时不套用该恢复；不要清空登录目录来试错。
- 明确上下文已满：失败轮保持失败，下批新消息另建线程，使用最近最多100条有效历史和检索记忆。旧绑定/历史不删，失败消息不自动回放；普通升级不会重置全部线程。手工重置仍不重新注入重置前历史，两种语义不同。
- 只发出部分回复：运行记录展开“发送顺序与部分结果”，查看已发送、失败、未发送及实际消息 ID。一次失败或权限变化停止余下动作，不自动重发；已发到QQ的消息不会撤回。静默、仅表情或一次短答都是合法模型选择。
- 记忆没出现：查看本轮实际使用条目。已结束话题不进入普通检索，未命中不会灌入全部笔记；可编辑类别/真实QQ/话题状态或按需要置顶。来源只读，机器人尚未发送的计划不算经历。
- 鸣潮绑定未完成：原群 @申请人的链接仅提供登录入口，SMS后还需核对账号摘要并由同QQ确认；过期重申请，勿转发链接。本人明确ww签到/解绑/订阅指令无需二次消息，模型发起修改仍需本人确认；引用/转发/他人不能代授权。
- 作者授权保存后仍不可用：已保存不等于服务已验证；分别查看WavesToken排行与xwtoken评分的待验证/拒绝/服务故障状态。空密码框保留旧值。不要把授权或玩家凭据贴入QQ、日志和Issue。B-AT缺失、无本人角色、无真实评分图不算成功。

旧版章节中的验证数字/限制属于其历史版本；本候选实际通过、失败和未验项只以[验证记录](VALIDATION.md)为准。
