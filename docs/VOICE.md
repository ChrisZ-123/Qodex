# QQ 语音转写（实验性）

公开版 `qodex-v0.5.0` 默认关闭自动语音读取。全局开启后，会话可选择继承、开启或关闭；分会话 `null` 表示继承。已开始的一轮沿用其设置快照，下一轮使用新设置。它请求 SnowLuma 的 `get_record_text` 使用 QQ 原生转写，并非 Qodex 自带独立 ASR 服务。

开启时，放行会话的新语音及明确引用的同会话语音可读取文字。文字保留原消息、说话人和时间，标示可能有误；引用内容仍属于被引用者的旧消息，不成为引用者的新指令。是否回复仍由当前 Codex 模型判断。历史可展开转写/失败详情，运行记录单列转写耗时，不计入模型耗时。

历史截图和本机报告确认机器人收到了语音、SnowLuma 找到对应消息并请求转写，但多条新语音失败或超时。用户认为可能与本机环境有关，根因尚未确定。截图只能证明接收语音并返回失败提示，不能据此确定 QQ 服务、账号或消息本身的问题，也不能证明所有语音无法转写。**本次历史真实语音“听懂并回复”未通过，发布版不承诺稳定 ASR。**截图中的失败提示不应被解读为成功识别。

每轮最多5条语音、单条最多30秒、整轮总预算60秒。失败、超时或空文字明确提示，不自动重试、不猜测内容、不静默调用另一家服务。其他已取得文字仍可使用。暂停期间只存消息，恢复不补转写；结果只在本会话复用。

不下载或长期保存音频，不识别声纹/情绪/背景声音，不发送语音回复。合并转发内语音暂只显示类型，不自动转写。旧消息可能已无法读取，依接口结果为准。

备份包含非敏感开关；只有可选历史才包含转写文字和来源元数据，音频不导出。完整升级仍须按[升级指南](UPGRADE_V050.md)备份本机数据。若需要稳定转写，需另行确定识别方案、资源和隐私边界；此版没有自动安装或切换模型。
