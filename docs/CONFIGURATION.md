# 配置说明

首次安装优先使用根目录 `Install.bat`，配置检查可直接使用 `Setup.ps1`（也可运行 `npm run setup`）。以下说明与 `config.example.json` 一起用于审阅生成的 `config.json`；示例文件没有真实账号、令牌或本机路径。配置文件和 `state/` 都不会被 Git 跟踪。手工更改模型、`consolePort` 或 `controlPort` 时，先用**旧配置**执行 `Control.ps1 -Action Stop`，再修改配置、执行 `Start` 和 `Verify`。先改控制端口会使旧进程无法通过新端口停止。

## Codex 与会话

| 字段 | 含义 |
| --- | --- |
| `backend` | 发布版使用 `codex`。旧 DSH 代码仍在源码中，但不作为此预览版受支持的部署后端。 |
| `codex.exe` | 原生 Codex CLI 可执行文件路径；留空时由运行环境发现。某些 `.cmd` 包装器不能作为子进程启动。 |
| `codex.conversationMode` | 发布版为 `model`：把允许的消息交给模型自主决定是否接话。 |
| `codex.model` | 需要当前 ChatGPT 账号支持的模型；默认示例为 `gpt-6-luna`。 |
| `codex.reasoningEffort` | 推理强度；示例为 `max`，与模型一起检查可用性。 |
| `codex.serviceTier` | `default` 或空值为标准速度，`priority` 为可选加速档位。不保证实际耗时按固定倍率缩短，也不会自动回退。 |
| `codex.autoCompactTokenLimit` | 留空使用 Codex 模型默认压缩阈值；可在控制台填写 8,000–1,000,000 token。它控制 Codex 原生上下文压缩时机，不扩大模型最大窗口，也不删除本地历史或长期记忆。 |
| `chatMemory.directory` | 每个群/私聊的长期记忆位置；默认 `state/chat-memory`。相对路径从**仓库根目录**解析，也可使用绝对路径。 |
| `state/codex-home` | 本部署独立的官方 Codex 登录与原生会话目录；由登录脚本创建，不写入公开配置或 JSON 备份。 |
| `state/generated-images` | 本部署生成的图片文件；控制台备份只记录元数据，整套回退需另行备份文件。 |
| `sessionCwd` | 旧会话工作目录字段；普通使用保持空值。 |

Codex 账号必须是 ChatGPT 登录类型；仅配置 API key 不可用。控制台的全局模型与推理强度是会话的默认值，保存在本部署 `config.json`，不修改 Codex 桌面端全局模型。速度与压缩阈值也是全局值。已开始的任务保持本轮快照，变更从下一轮生效；修订已变化时须刷新后重试。模型有权选择不回复，原生网页搜索也由模型按需使用；配置 `web_search: live` 不等于每轮自动联网。

### 当前会话覆盖与优先级

控制台“当前会话独立设置”保存到 `state/model-preferences.json`，按 `group:<QQ 群号>` 或 `private:<QQ 号>` 隔离；没有覆盖项时继承全局。模型和推理强度成对选择，必须是当前账号可用组合；全局模型变化不会替换已有的会话覆盖。角色可继承全局、选用某张角色卡，或明确设为“无角色”；独立口吻最多 4,000 字符，也可恢复继承。回复方式 `replyMode` 为 `natural/single`，缺省为 `natural`；会话 `null` 继承。`single` 要求模型原生组织一段文字，不在输出后拼接，QQ 限制仍可能传输分片。图片生成 `imageMode` 为 `off/requested/auto`，表情倾向 `stickerStyle` 为 `natural/lively`；分会话的 `null` 表示继承。未设置时分别使用 `requested` 和 `natural`。已有本机设置仍以其保存值为准。分会话设置不覆盖全局速度与压缩阈值。

全局暂停与各会话暂停持久化；任一级暂停都会阻止该会话后续消息进入模型。暂停期间消息仍记入本地历史，恢复后从新消息继续。取消“当前回复”只请求终止正在执行的一轮，不删除后来排队的新消息；若终止未获确认，运行记录会显示“取消未确认”，应等待它结束或重置该会话。上下文重置取消当前及排队回复，保留历史、人格、长期记忆及其他会话，下条消息建立新 Codex 会话且不重新注入重置前历史。已经发到 QQ 的消息无法撤回。

### 条目记忆与反馈

每个会话的记忆文件位于 `chatMemory.directory` 下对应的 `group-<id>/memory.json` 或 `private-<id>/memory.json`。schema 2 存储 `entries`、来源、逐条版本和整体 `revision`，有效内容最多 30,000 字符。首次读取旧 `content` 格式时会先保留 `memory.json.legacy-v1.json`，再转换为条目；旧版程序不能直接读取转换后的文件。管理员可新增、编辑、置顶、停用和恢复旧版；置顶条目不会被模型改写。每轮优先提供全部有效置顶记忆，条目类别为 `fact/person/episode/topic`，含真实 QQ 参与者、来源与可核对的补充证据，话题有结束状态；旧条目按 `fact` 兼容读取，既有来源与版本不丢失。普通检索先考虑当前发言者的人物记忆，再按本地中文分词与 BM25 正相关选择其他条目，已结束话题不进入普通检索；无命中不灌入全部笔记。最多 12 条、目标 6,000 字符。置顶内容超过预算时仍完整提供，并提示本轮未追加普通条目。

机器人在同一模型回合逐条提出记忆更新，无需第二个模型调用；只能修订本轮检索到的普通条目，并引用本轮可核对的来源消息。人物来源必须来自实际发言者；已确认发送的机器人历史才能作为补充证据，本轮尚未发送的回复不能充作经历。给机器人回复添加“多余”“太长”“合适”反馈后，该会话的提示会在后续回合柔性参考；撤销即从有效反馈中移除。记忆和反馈都属于本机记录，**不会训练模型权重**。关闭记忆后不会再检索或自动更新；旧聊天历史可能仍含相关信息。

## SnowLuma 与访问

Windows 向导要求以下三个 URL 使用字面量 `127.0.0.1` 和显式端口；不接受 `localhost`、IPv6 地址或省略端口。OneBot HTTP、WebSocket、SnowLuma WebUI、控制台、控制服务五个端口必须各不相同，端口范围为 1024–65535。

| 字段 | 含义 |
| --- | --- |
| `snowluma.wsUrl` | 本机 OneBot WebSocket 服务端；默认 `ws://127.0.0.1:3001`。 |
| `snowluma.httpUrl` | 本机 OneBot HTTP API；默认 `http://127.0.0.1:3000`，不要填 WebSocket 端口。 |
| `snowluma.webUiUrl` | SnowLuma 管理页地址；默认 `http://127.0.0.1:5099`。 |
| `snowluma.launcherPath` | 可选的本机启动器路径；启动 Qodex 时若 OneBot WebSocket 尚不可达，管理进程会尝试启动它。`OpenSnowLuma` 只打开 WebUI。SnowLuma 需单独安装。 |
| `snowluma.accessToken` | 示例留空；向导会安全询问 OneBot 令牌并存入 `state/secrets.dpapi`，不要写入公开配置或 Issue。 |
| `ownerQQ` | 管理员 QQ 号。 |
| `allow.groups` / `allow.private` | 允许接入的群号和私聊 QQ 号数组；默认空。 |
| `deny.groups` / `deny.private` | 黑名单，优先于白名单。 |
| `allowAllWhenEmpty` | 保持默认 `false`：白名单为空时拒绝所有消息。设为 `true` 会扩大访问范围。 |

群聊的全体发言在放行后会进入该群独立会话，由模型判断是否接话；`ownerQQ` 不意味着管理员普通群发言必须得到回复。不要将 OneBot、控制台或控制接口直接开放到公网。需要改访问范围时，可使用本机控制台的“群聊与访问权限”界面。

## 控制台、历史与表情

| 字段 | 含义 |
| --- | --- |
| `consolePort` | 本机控制台端口，默认 3100。 |
| `controlPort` | 本机控制接口端口，默认 3110。 |
| `consoleToken` | 控制台访问令牌；安装时在本地生成并保管，不要分享。 |
| `ackMessage` | 消息收到后的提示文本；默认空，不额外发送即时确认。 |
| `sendDelayMs` | 连续发送的基础间隔。 |

控制台可管理全局人格、聊天口吻、白名单、会话历史、暂停、每个会话的条目记忆与反馈、表情图库及运行记录。运行记录保留最近 100 轮，显示阶段、排队/转发读取/模型/生图/发送时间、搜索次数和累计耗时、实际用到的记忆及 QQ 发送结果；错误会先脱敏。原生协议 `protocolVersion:2` 的 `replyActions` 按顺序包含 `text/sticker/generatedImage/wavesImage`；每轮最多四段文字、两张不同收藏表情、一张生成图及二十张不同鸣潮结果图。先校验整轮和资源，再逐次核对任务/取消/暂停/访问与禁用，失败停止剩余发送，不重试；只有第一条实际消息附引用。开启“收藏表情看图学习”时，每轮最多向当前模型提供两张尚无备注的收藏图；笔记和图片资料供各允许会话共用。图库禁用只阻止机器人选择该表情，不会删除 QQ 收藏。自动收藏只处理**允许群**里 OneBot 明确标记为表情的图片；普通群图和私聊图片不会自动收藏，到 100 张时暂停新增。手工在 QQ 收藏的表情可在控制台同步。

控制台 JSON 备份导出允许的设置、角色文本、会话覆盖、记忆及修订、反馈、表情备注和生成图片元数据；聊天历史默认不含，可在下载前勾选。导入会先校验格式与账号模型可用性，再显示差异并选择项目；执行前自动写 `state/restore-snapshots/` 快照。恢复会停止进行中的回复；空闲会话仅在其设置、记忆、历史或所引用的全局设置与角色受恢复影响时重建模型上下文。它不含本机凭据文件、Codex 登录/会话绑定、生成图片本体和完整运行文件，即使包含历史也**不是整套部署回退镜像**。缺少对应图片文件时历史预览会显示不可用。文本字段虽经过已知模式脱敏，仍可能包含未识别的私人资料或凭据，下载后请妥善保管，分享前自行检查。恢复不会重发历史消息。见[接口说明](CONSOLE_API.md)与[升级指南](UPGRADE_V040.md)。

`state/` 含会话历史、记忆、表情资料、日志以及本地令牌状态，应视为私有数据备份。显式设置仓库外 `chatMemory.directory` 时，完整备份和迁移须额外包含该目录。不要把本机真实文件、`config.json`、`state/` 或 `*.dpapi` 提交到 Git。

## 语音与鸣潮

全局表达设置的 `voiceEnabled` 默认 `false`（实验性语音转写）；当前会话同名字段为 `null/true/false`，`null` 继承全局。它依赖 SnowLuma/QQ 原生转写，已有接收语音但转写失败的实测记录，不能保证稳定 ASR。详见[语音说明](VOICE.md)。

`config.waves` 为本机运行配置，与游戏开关分离：

```json
{
  "rpcPort": 8788,
  "loginPort": 8789,
  "tunnelMetricsPort": 8790,
  "remoteLoginEnabled": false
}
```

端口须为可用且与其余服务不同的本机端口，修改前用旧配置停止本部署。`remoteLoginEnabled:false` 为公开默认；开启游戏不等于启用远程绑定。

非敏感游戏开关存于 `state/waves-settings.json`：`version:1`、整数 `revision`、全局 `enabled:false` 和 `conversations` 映射。当前会话值 `null` 继承，布尔值显式覆盖；全局关闭优先。两分区共用会话选择，保存各区设置不覆盖另一区未保存草稿。保存需使用当前修订号；旧修订返回409。开启同步本部署游戏监督进程与会话策略，模型工具在下个空闲点/新线程生效；未启用或未安装会话保留原绑定与聊天批处理。首次开启提示新线程将载入最近100条有效消息及检索记忆，并保留全部本地历史、记忆与旧绑定供回退。

可选模块运行目录为 `state/waves`，含 `core`、`venv`、`data`、`inputs`、`results`、`browsers`；发布Python源码及补丁在 `integrations/waves`。原有 `state/codex-home`、`state/generated-images` 和记忆目录独立保留。

JSON v1备份兼容v0.4.0，保留回复方式、分类记忆元数据、可选历史轮次/顺序，以及非敏感语音/游戏开关和转写来源元数据。它不包含音频、游戏账户/凭据、票据、订阅、图片本体或远程绑定启用配置；恢复不会开启自动任务。完整回退见[v0.5指南](UPGRADE_V050.md)。

文件恢复成功后按恢复的设置协调鸣潮策略和本部署所属服务，返回 `policySynced`；失败附脱敏 `policyError` 并提示同步不完整，不将文件已恢复误报为服务已就绪。暂停或撤权后，控制台仍可纯停用已有订阅，不能借此新开订阅。

## v0.6.0 作者服务授权

鸣潮控制台提供 WavesToken/xwtoken 独立或共用保存，留空保留现有值；凭据由 DPAPI 独立保存，不写普通 JSON，不纳入备份。已配置、实际请求验证、授权拒绝与服务故障分别显示；保存不代表已验证。玩家登录与作者授权相互独立，完整契约见[鸣潮指南](WAVES.md)。
